# RoutePack B1 forward-only integration gate

> 最终状态：GPU run `routepack-b1-20260912-02` 全部 8 rank 通过；普通前向 / R3 / Engine 的 128 个 response logprobs bits 一致，实际路由差异 0，optimizer steps 0。独立 B2 数组复核亦通过，见 [最终报告](REPORT.md#最终实际验收b1-通过b2-计数链通过)。早期未运行状态保留为执行历史。

本轮新增独立的 `tools/routepack/b1_gate.py` 和 `prepare_b1.py`，复用现有 Megatron/Ray 初始化与原生 rollout schedule，不运行 optimizer 或 backward，不更改在线 scheduler。

## 运行链

1. 使用同 checkpoint 的 aligned Engine baseline capture；每条样本必须包含真实 token、48 层 top8 route，以及逐 response token FP32 logprob。旧 capture02 没有保存 logprob，因此不能单独通过本 gate。
2. `prepare_b1.py CAPTURE OUTPUT.pt` 校验 token/route hash、shape、逻辑 expert 范围、topk 唯一性和 logprob 覆盖，生成基本 Python 类型及 Tensor 构成的 debug rollout，随后用 `weights_only=True` 读回检查。reward=0 是该 forward-only 输入的未使用占位符，不作为训练奖励或性能数据。
3. 对已展开的 v89 options/env 调用 `routepack.b1_gate.configure_launch(options, env, run=RUN, rollout_path=OUTPUT)`。该函数冻结 `--debug-train-only`、R3 env/flags、init hook、显式起点 0/一次 rollout、lr=0、effective logprob temperature=1.0。Engine greedy temperature=0 的实际 logprob 是未缩放 log-softmax；训练已有 `_rollout_logprob_temperature` 同样将 greedy 0 映射为 1。
4. custom Megatron init hook 仅将本次 worker 的 `train_actor` 替换为两次 `compute_log_prob`：aligned fallthrough 与 R3 replay_forward。初始化/权重加载/原生 schedule 未替换，依然需要原始训练资源。无 backward 的 R3 pass 只检查 forward 消耗，不能声称训练 backward R3 gate 通过。

运行入口使用独立 `routepack` 包。启动环境及 Ray worker 环境需要保留以下前置路径（`configure_launch` 已自动写入 worker env）：

```bash
export PYTHONPATH="/public/home/yingxy2024/moe-consistency/slime/tools:${PYTHONPATH:-}"
```

```text
--custom-megatron-init-path routepack.b1_gate.install
--custom-megatron-before-log-prob-hook-path routepack.b1_gate.before_log_prob
```

若只导出 topology 而不运行完整 B1 gate，使用 `routepack.runtime_topology.aligned_before_log_prob`。不要在可执行 hook 路径中使用 `tools.routepack.*`；下文的该旧名称仅保留为 B1-01 失败证据。

## 实际观测边界

- alignment hook 后导出真实 process group 成员及每层 local expert owner。
- router forward hook 保留有序 topk，同时在真实 `_DeepepManager.dispatch` 调用上下文中拦截第一条 `deep_ep.Buffer.dispatch(..., topk_idx=...)` primary payload。读的是传给实际通信函数的参数，不能由 manager/wrapper 缓存冒充。
- 后续 alignment metadata-only dispatch 不当成 primary payload。函数仍原样执行，观测只增加同步/CPU拷贝/文件输出，不能作为性能计时。
- 两个边界均按原生 microbatch slot 的 sample_index/token_position/layer 对齐。fallthrough 只比较真实 trace rows；R3 另检查按生产 padding 函数产生的 terminal 和 bin padding。
- 逐 rank 保存原生 schedule、完整 router/dispatch int32/int64 numpy IDs、逐样本 aligned/replay/rollout FP32 logprobs，以及 `gate.json`。logprobs按 uint32 bits 比较。
- 要求每个 rank 两个 pass 的 router 和 primary dispatch 覆盖所有 48 层、所有 microbatch，R3 所有层消费一次，再验证所有 rank gate.json 完整且 passed。

统一 launcher 的 v89 args/env、debug-only Engine/权重同步跳过、R3 worker env、原生 Sample.from_dict 与 route shape 验证契约已核对。发现 Ray `_inject_tracing_into_class` 会将 `train_actor` 包装复制到动态子类；仅修改导入基类不足以替换正在运行的 actor 方法，可能误入原始训练。现 init hook 通过本 worker 的实际 actor 实例绑定 forward-only 方法并断言绑定成功。6 项 B1 CPU 回归通过；另在目标 slime Python 环境用真实 Ray `_modify_class` + tracing 注入完成无 Ray 服务/GPU 的绑定验证。

## B1-01 实测启动失败与包路径修复

`routepack-b1-20260912-01` 实际完成 Ray/8 GPU placement 及训练进程组初始化，但在加载 custom init hook 时失败：`ModuleNotFoundError: No module named 'tools.routepack'`。原因是实际 Megatron 提供普通包 `Megatron-LM/tools/__init__.py`，而本项目 tools 是 namespace directory；前者遮蔽后者。该失败发生于模型加载及 B1 forward 前，不能计作路由不一致。

主任务确认 B1-01/Ray 已退出后，hook 改用独立 `routepack.b1_gate`，`configure_launch` 在 worker PYTHONPATH 添加本项目绝对 `slime/tools` 路径。没有给通用 tools 加 __init__.py，也没有修改 Megatron tools。目标 slime Python 的 CPU 验证先加载真实 Megatron tools，复现旧失败，再保持该模块已加载的情况下调用实际 `slime.utils.misc.load_function`，两个新 hook 均成功加载。6 项 B1 CPU 回归继续通过；后续 B1 重跑使用新 run ID。
